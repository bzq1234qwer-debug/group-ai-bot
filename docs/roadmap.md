# 路线图（v1 引流版 → 后续升级）

> 目标：v1 能发给别人用、能跑住、能传播；v2 再谈规模化。

---

## 一、你刚提的两件事

### 1. 用户自己配置到服务器

**为什么重要**：这是当前最大矛盾的解药。现在的形态要求"一台常开的电脑"，把 90% 的潜在用户挡在门外。支持服务器后：

- 用户用自己的 VPS / 云服务器（¥30~60/月，比一台常开电脑便宜）
- 关机、断网、出差都不影响
- 手机浏览器就能管

**实现形态**：

| 方式 | 说明 | 适合 |
|---|---|---|
| Docker 一键部署 | `docker compose up -d`，镜像里包含 NapCat + 运行时 | 有点基础的用户 |
| 一键脚本 | `curl -fsSL ... \| bash`，自动装依赖、拉镜像、起服务 | 主流 |
| 云厂商镜像 | 打包成"应用镜像"，买服务器时直接选 | 最省事，但要和云厂商合作 |

**必须先做的安全设计**（不做就是灾难）：

1. **强制鉴权**：控制台现在只监听 `127.0.0.1`，一旦暴露到公网，任何人能控制用户的机器人、看到 Key、给他群发消息
2. **HTTPS**：至少给个反代模板（Caddy/Nginx），否则密码明文过网
3. **首次访问设密码**：不能有默认密码
4. **端口收敛**：只暴露一个入口（控制台），NapCat 的 WS 和 WebUI 都不对外

### 2. 自动更新

**为什么重要**：NapCat 和 QQ 版本一变就失效，你不能指望用户手动重装。

**分两层**：

| 层 | 做法 | 注意 |
|---|---|---|
| 桌面端（exe） | 启动时拉版本清单 JSON → 有新版提示 → 下载替换 | 必须校验签名/哈希，否则是供应链攻击面 |
| 服务器端 | `docker pull` 新镜像 / 脚本自更新 | 更新前备份 `data/` |

**更新通道**：你自己托管一个 `latest.json`（版本号、下载地址、sha256、更新说明），别依赖 GitHub Releases（国内慢）。

## 二、还能延展什么

按"对引流 v1 的价值"排序。

### A. 运维与部署（你提了两条，这里补齐）

| 项 | 价值 | 优先级 |
|---|---|---|
| 一键部署到服务器 | 解决"电脑关机" | **P0** |
| 远程管理（手机浏览器） | 免装 App | **P0** |
| 自动更新 | 规模化必需 | **P0** |
| 配置导出/导入（zip） | 本地↔服务器迁移、换机不丢 | P1 |
| 健康检查 + 掉线告警 | 用户不用猜"它为什么不说话" | P1 |
| 开机自启 / 崩溃重启 | 跑得住 | P1 |
| 多实例管理（一个面板管多个号） | 多号用户 | P2 |

### B. 稳定性与风控

| 项 | 说明 | 优先级 |
|---|---|---|
| 掉线检测 | 定时 `get_login_info`，失败标红 + 通知 | **P0** |
| 限流与防封 | 每群频率、随机间隔、夜间静默、新号冷启动降频 | **P0** |
| QQ/NapCat 版本兼容检测 | 启动时比对版本清单，不兼容就提示 | P1 |
| 单号故障隔离 | 一个号挂了不影响其他号 | P1 |
| 消息去重与重放保护 | 已有（幂等），加强边界 | P2 |

### C. AI 能力

| 项 | 说明 | 优先级 |
|---|---|---|
| 长会话摘要压缩 | ✅ 已做：每 30 条压一次，覆盖点之后不重复进上下文 | **P0** |
| 每日聊天记录归档 | ✅ 已做：按会话分文件夹，可配时间与保留天数 | **P0** |
| 全文检索记忆 | ✅ 已做：FTS5 + 中文字拆分词，索引不随工作副本清理，另有 10 万行总量上限 | **P0** |
| 摘要强化 | ✅ 已做：强制保留数字/时间/承诺/称呼禁忌，丢掉寒暄 | **P0** |
| 多路召回 | ✅ 已做：关键词 + 同一人 + 最近加权 | **P0** |
| 结构化事实库 | ✅ 已做：`facts` 表，和摘要共用一次调用，新值覆盖旧值，代词主语拒收 | **P0** |
| 记忆管理界面 | ✅ 已做：控制台能看到「它记住了什么」，可逐条删除 | **P0** |
| 工具调用 | 查天气、搜索、算数（DeepSeek 支持 tool calls） | P1 |
| 看图说话 | `deepseek-flash` 支持 vision，群里有人发图它能接 | P1 |
| 表情包/图片 | 已做一半，真机未验证 | P1 |
| 人格模板市场 | 用户可分享/导入人设 —— **天然传播点** | P1 |
| 语音回复 | 成本高、延迟大 | P3 |

### D. 增长与传播（引流版的关键）

| 项 | 说明 | 优先级 |
|---|---|---|
| 一键生成"分享卡片" | "我家群友刚说了这句话"截图卡，带二维码 | **P0** |

| 官网 / 落地页 | 安装包 + 教程 + 演示视频 | P2 |

### E. 平台扩展

|---|---|---|
| QQ 频道 | 官方接口，合规，可作为"备份通道" | P2 |

### F. 商业化（v2 再说）

| 项 | 说明 |
|---|---|

## 三、v1 建议范围（别摊大饼）

**做这 8 件，其余全部推后：**

1. ✅ 一键启动器（双击即用）—— 启动.bat / 停止.bat / 开机自启.bat
2. ✅ 开机自启 + 崩溃重启 —— 自启完成；崩溃重启待做
3. ✅ 首屏向导（检测环境、给步骤）—— 六项自检 + 一键补
4. ✅ 风险提示 + 免责确认 —— 首次强制勾选，条款带版本号
5. ✅ 日志落盘 + 一键导出 —— 按天写 `data/logs/`，保留 7 天；诊断包含 NapCat 日志并自动脱敏
6. ✅ 掉线检测 + 通知 —— 30 秒探活 `get_login_info`，连续两次失败判离线
7. ✅ **服务器一键部署（Docker）** —— docker compose + deploy.sh + 控制台令牌鉴权
8. ⬜ **自动更新**

补充完成：
- ✅ 自动下载安装 NapCat（控制台里点「自动安装」）
- ✅ 把 Node 打包进 `runtime\`（双击「准备运行环境.bat」）

**明确不做（v1）**：多号 UI、微信、语音、工具调用、商业化。

## 四、v1 的验收标准

一个没装过 Node、没听过 NapCat 的人，能做到：

1. 下载一个安装包
2. 双击，跟着向导走
3. 扫码登录自己的小号
4. 填 Key
5. 在群里 @ 它，它回话

**全程不超过 10 分钟，不打开任何命令行窗口。**

达不到这五条，就别谈引流。
