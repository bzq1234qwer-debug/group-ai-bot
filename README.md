# 群聊 AI 助手

**产品定位：一个配置工具。** 帮用户把 DeepSeek 接进自己的 QQ 小号——小号就是机器人，用户填自己的 API Key，它就像群友一样在群里说话、被 @ 时回话，支持多个群。

不是"提供一个公共机器人让人来用"，而是"让每个人把自己的小号变成 AI"。
所以核心体验在**配置流程**：扫码登录小号 → 填 Key → 选群 → 完成。

## 两种用法（已定）

| 你是 | 怎么用 | 需要什么 |
|---|---|---|
| **普通用户** | 双击「启动.bat」，让电脑挂着 | 一台能常开的 Windows 电脑 |
| **技术人员** | Docker 部署到自己的服务器 | 会 SSH、会装 Docker |

**我们不做托管。** 服务器、账号、Key 都是用户自己的，我们不碰。

这个决定带来一个必须承认的结果：**普通用户关机，它就不在线。** 这是接受的代价，
换来的是最少的合规风险和售后负担。

## 记忆与归档

**记忆（滚动摘要）**：每累积 30 条消息，把快掉出窗口的那部分压成一段摘要，关键事实（谁是谁、约定了什么、它的规矩）会一直带着走。摘要覆盖点之后的消息不再重复进上下文。

实测产出的摘要长这样：

```
- 小明是群里的活跃用户，多次主动找"我"（自称"本鱼"）搭话。
- 我的规矩：不喜欢被叫"大肥鱼"，被叫会纠正；反感光喊"在吗"不说事。
```

**归档（每日聊天记录）**：每天定时把当天记录写出来，**按会话分文件夹**：

```
data/archive/2026-10-24/
  _index.md
  qq-10001-private-20002/chat.md
  qq-10001-group-30003/chat.md
```

可在控制台改执行时间、保留天数，或点「立即归档」。

> 为什么需要它：数据库里每个会话只留最近 2000 条"工作副本"（再多对对话没用，只会拖慢查询）。
> 更早的话只剩两条路能找到——**全文索引**（能想起来）和**归档文件**（能翻到原文）。
> 归档是唯一人类可读的长期记录。

**它记住了什么**：控制台有一张卡片，列出它从聊天里提炼的长期事实——

```
小明 · 偏好 = 习惯称呼对方为「大肥鱼」
大肥鱼     · 偏好 = 自称"本鱼"，不喜欢被叫"大肥鱼"
本群       · 群规 = 不许发广告、不许拉人
```

每条都能删。删掉之后它就不记得了——**记忆应该可见、可改、可删**。

## 部署到服务器（让机器人 7×24 在线）

电脑关机它就没了。放到服务器上，关机、断网、出差都不影响。

```bash
scp -r group-ai-bot 用户@服务器:/opt/
ssh 用户@服务器 && cd /opt/group-ai-bot
bash deploy.sh
```

会自动生成访问令牌、拉起两个容器（NapCat + 运行时）、打印控制台地址。

**三步之后还要做一件容易漏的**：在 NapCat WebUI 里开一个 WebSocket 服务（端口 3001，host `0.0.0.0`），否则容器里的运行时连不上。

完整步骤、SSH 隧道、HTTPS 反代、常见问题见 [docs/server.md](docs/server.md)。

> 安全前提：控制台设了 `CONSOLE_TOKEN`，所有接口都要令牌；NapCat 的 6099 只绑本机，走 SSH 隧道访问。**别把 6099 暴露到公网**——那等于交出账号操作权。

## 使用前必读（风险提示）

**这不是常规软件。** 它会在腾讯的平台上替你操作一个真实账号。

1. **非官方接口** —— 通过 NapCat 注入，不是腾讯开放能力，违反其用户协议
2. **账号可能被封** —— 自动化操作真实账号有风控、限制、封禁风险
3. **必须用小号** —— 主号被封，损失不可逆
4. **后果自负** —— 账号风险由使用者承担，作者不承担赔偿
5. **数据边界** —— Key/记录/配置只存本机；对话内容会发给 DeepSeek 生成回复
6. **禁止滥用** —— 骚扰、群发广告、诈骗等违法用途

控制台首次打开会强制显示这份条款，勾选确认后才能使用。条款版本号变了会重新要求确认。

## 最快上手：双击，不开命令行

前提（各装一次）：QQ NT、[NapCat](https://github.com/NapNeko/NapCatQQ)（或让控制台自动装）、[Node.js](https://nodejs.org/)（或双击「准备运行环境.bat」自动下载）。

| 文件 | 作用 |
|---|---|
| **启动.bat** | 起 NapCat → 起控制台 → 开浏览器。已经在跑的会自动跳过，不会起第二份 |
| **停止.bat** | 只停控制台（按 PID，不误伤别的 node）；会问你要不要连 QQ 一起关 |
| **准备运行环境.bat** | 把 Node.js 下到 `runtime\`，以后不依赖系统装 Node |
| **开机自启.bat** | 开机自动启动，最小化，不弹黑窗口 |
| **取消自启.bat** | 取消开机自启 |

启动后浏览器自动打开 http://127.0.0.1:7799 ，关掉浏览器不影响运行。

控制台打开第一眼是**上手向导**：自动检查 QQ / NapCat / 登录 / Key / 选群，缺什么显示什么，能一键补的（启动 NapCat、下载 NapCat）直接帮你做。五项全绿后卡片自动消失。

## 电脑端：配置控制台（主入口）

```bash
npm run console        # 打开 http://127.0.0.1:7799
```

不用改 JSON、不用设环境变量，网页上五步：

1. **加号** —— 填备注名 + WebSocket 地址（SnowLuma/LLOneBot）或 HTTP 地址（NapCat）
2. **连接** —— 显示在线状态；用 HTTP 方式的，会生成一个「上报地址」，填回 NapCat
3. **勾群** —— 列出这个号所在的群，勾上哪个，AI 就管哪个
4. **填 Key** —— 带「测试」按钮，不通会告诉你原因
5. **保存人设** —— 名字、人设、什么时候说话（只回 @ / 自己插话）、冷却、话题词

所有配置存在 `data/console.json`，重启自动恢复。

## 方式 A：QQ 官方机器人（可以装进 APK）

### 1. 建一个机器人（约 10 分钟）

1. 打开 <https://q.qq.com/>，用 QQ 号注册，完成**个人主体实名认证**
2. 进入机器人管理端 → 创建机器人（个人主体可建 5 个）
3. 在「开发设置」里拿到 **AppID** 和 **AppSecret**
4. 抄下你的机器人昵称

### 2. 把机器人拉进你的群（必须用最新版手机 QQ）

用**群主或管理员**的账号，在群里添加这个机器人。添加时会弹出权限设置：

- **只接收 @ 消息** —— 够用，推荐（默认策略就是只回 @）
- 想让它看全群聊天并主动发言，才需要开「接收全量消息」「主动推送」

> 个人主体的机器人，**只有创建者本人**能拉进自己当群主/管理员的群。这是腾讯的规则，绕不过去。

### 3. 配置并启动

```bash
cp config.qqbot.example.json config.json
```

把 `appId`、`channels[0].id`（`qqbot:<你的AppID>`）、`bindings[0].convKey` 里的数字都换成你的 AppID。

```powershell
$env:QQBOT_APP_SECRET="你的AppSecret"
$env:DEEPSEEK_API_KEY="sk-你的key"
node src/main.ts --config config.json
```

注意 `bindings` 用的是**通配符** `qqbot:102030405:group:*`。原因：群的 `group_openid` 你事先不可能知道，要等机器人收到第一条消息才有。通配符让你不必知道——机器人进任何群都自动接管。

启动后去群里 @ 一下，日志里会出现 `生成中` → `完成 in=… out=… 花费≈¥…`。

### 4. 关于 AppSecret 存放

**别写进 config.json。** 那个文件是给用户看的、会到处传。用环境变量 `QQBOT_APP_SECRET`，或者等后续版本的本机加密存储（APK 里用 Android Keystore）。

## 对接抖音那套（SnowLuma / OneBot v11）

这几天抖音/B站很火的那条「把 DeepSeek 大肥鱼拉进 QQ 群」，链路是：

```
QQ 客户端 ←注入← SnowLuma（对外暴露 OneBot v11）
                        ↓
                   qq-bridge（本地 HTTP + Token 鉴权）
                        ↓
                   DSH（填 API Key 调模型）
```

拆解参考：[控场AI 的逐段分析](https://kongchang.com/articles/san-fen-zhong-ba-deepseekxiao-jing-yu-la-jin-qqqun-shou-ba-shou-jiao-cheng-yu-le)、[qq-bridge](https://github.com/Derpyu520/qq-bridge)（README 明写 "Bridge between QQ (SnowLuma OneBot v11) and DeepSeek Harness agents"）。

**关键点：SnowLuma 说的 OneBot v11，和我们 `adapters/onebot.ts` 是同一个协议。** 所以不需要另写适配器，只要改一个地址。

区别在连接方向。NapCat 一般是「我们开 HTTP 服务，它上报（反向 HTTP）」；SnowLuma 一般只开「正向 WebSocket」，要我们主动连过去。所以适配器现在两种都支持：

| 模式 | 配置 | 适用 |
|---|---|---|
| 反向 HTTP | `baseUrl` + `eventPort` | NapCat |
| 正向 WebSocket | `wsUrl` | **SnowLuma**、LLOneBot |

```jsonc
{
  "channels": [{
    "id": "qq:10001",
    "kind": "onebot11",
    "selfId": "10001",
    "baseUrl": "http://127.0.0.1:3000",
    "wsUrl": "ws://127.0.0.1:3001",   // 配了就忽略 eventPort
    "eventToken": "SnowLuma 后台给的 token"
  }]
}
```

完整示例见 [config.snowluma.example.json](config.snowluma.example.json)。

> 注意：这条路要一台常开的 Windows 电脑（注入的是桌面版 QQ NT），手机上跑不了。
> 同样是注入方案，SnowLuma 和 NapCat 的封号风险、版本失效风险完全一样。

## 平台规则（决定了这个产品的边界）

来自 [QQ 机器人官方 FAQ](https://bot.q.qq.com/wiki/bot_FAQ/)：

> **个人主体的机器人如需添加群聊，机器人创建者可直接添加自己是群主/管理员身份的群聊**
> **企业主体公开使用已开放，个人主体暂不支持公开使用**

翻译成人话：

| 你想做的 | 结论 |
|---|---|
| 你建 1 个机器人，别人把它拉进任意群 | ❌ 个人主体做不到 |
| 每个用户自己建机器人，拉进自己的群 | ✅ 可行，零服务器 |
| 注册企业主体（要营业执照），公开给别人用 | ✅ 可行，但你要买服务器 |

还有两条要知道：机器人带**明显官方标识**，不能伪装真人；内容违规会**封主体账号**，所以内容过滤不能省。

## 几个刻意的设计决定

**为什么分段消息全部挂在同一个 `msg_id` 上**
QQ 官方接口的"被动回复"窗口只有 5 分钟、最多 5 条。如果第 2 段不带 `msg_id`，它就变成"主动推送"——而主动推送需要群主额外授权，默认发不出去。所以适配器会复用同一个 `msg_id`、递增 `msg_seq`。

**为什么上下文默认只给 24K**
DeepSeek 是 1M 上下文，但价格随 token 线性涨。群聊消息量大，不设上限会失控。

**为什么默认关思考模式**
DeepSeek 当前模型 thinking **默认开启**，思考 token 按输出计费，群聊场景成本放大 3~10 倍，延迟也高。代码里显式传 `{"thinking":{"type":"disabled"}}`。

**为什么每条历史带 `[昵称 时间]`**
群里多人同时说话，模型必须知道哪句谁说的、什么时候说的。

**为什么 AppSecret 不进配置文件**
配置文件是交付物，会被复制、转发、贴进群里。
